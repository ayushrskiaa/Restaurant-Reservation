# 🍽️ Rskiaa's — React Native App (WebView wrapper)

This folder adds a **React Native (Expo) mobile app** to the `Restaurant-Reservation`
repo. The app does not re-implement the UI — it loads the **existing React web app**
inside a full-screen `WebView` and reuses the **same backend** exactly as the website.

```
Restaurant-Reservation/
├── backend/    # unchanged — reused as-is
├── frontend/   # unchanged — build & deploy it once, then point the app at it
└── App/        # 🆕 this folder — React Native wrapper
    ├── App.js               # root: WebView shell, back handling, error/loading states
    ├── src/
    │   ├── config.js        # web app URL + host allow-list
    │   ├── LoadingScreen.jsx
    │   ├── ErrorScreen.jsx
    │   └── PopupWebView.jsx # Razorpay / popup window support
    ├── assets/              # generated icons & splash (from frontend/public/logo_noBg.png)
    ├── app.json             # app config — ⚙️ set `extra.webAppUrl` here
    ├── index.js             # RN entry point
    ├── babel.config.js
    └── package.json
```

---

## 🧭 How it works

1. The app opens a `WebView` pointed at your **deployed frontend URL**
   (`app.json` → `expo.extra.webAppUrl`).
2. The web app's logic already detects it is *not* on `localhost`, so every API
   call goes to `VITE_PRODUCTION_URL` — i.e. **the same backend**, no changes.
3. The app enables `domStorageEnabled` (the web app stores its cart in
   `localStorage`) and shared cookies (for `withCredentials` calls).
4. Razorpay opens a popup (`window.open`) during UPI/Card checkout.
   Android WebViews don't render popups natively, so the app captures the
   `onOpenWindow` event and presents the checkout in a secondary WebView
   (`src/PopupWebView.jsx`).

## 🚀 Quick start (dev)

Prerequisites: **Node 18+** and the **Expo Go** app on your phone.

```bash
cd App
npm install

# start the dev server
npx expo start
```

- **Android:** scan the QR code with Expo Go (or press `a` for an emulator).
- **iOS:** scan with the camera app → opens in Expo Go (or press `i`).

> Expo Go loads the app over your LAN, but the `WebView` points at the deployed
> website, so no backend needs to run on your machine to try it.

## ⚙️ Configuration

### 1. Point the app at your deployed frontend

This repo's app is already configured with the live deployment:

```json
"extra": {
  // 👇 Frontend deployment (Vercel) — verified live
  "webAppUrl": "https://restaurant-reservation-self-five.vercel.app",
  // 👇 Backend deployment (Render) — the web app's VITE_PRODUCTION_URL
  "apiHosts": ["restaurant-reservation-1jia.onrender.com"]
}
```

If you deploy elsewhere, edit `App/app.json` accordingly.
> You can also set `EXPO_PUBLIC_WEB_APP_URL` in the environment — it overrides
> `webAppUrl` (useful for staging vs. production builds).

### 2. Backend CORS (no code changes, just env)

The backend whitelists origins via `FRONTEND_URL_*` env vars
(`backend/.env`). The live backend already returns
`Access-Control-Allow-Origin: https://restaurant-reservation-self-five.vercel.app`
with `credentials: true`, so **no CORS change is required** for the current
deployment. If you deploy a different frontend origin, add it to
`FRONTEND_URL_*`:

```
FRONTEND_URL_PROD=https://your-deployed-frontend.example.com
```

No `frontend/` or `backend/` source changes are required.

## 🔐 Host allow-list & external links

`src/config.js` declares which hosts may be rendered inside the WebView:

- the **web app host** (derived from `webAppUrl`)
- `razorpay.com` and its subdomains (checkout)
- image CDNs used by the site (`res.cloudinary.com`, `images.pexels.com`)
- Google Fonts
- `localhost` / `127.0.0.1` for local development

Anything that is **not** on the allow-list and loads as a **top-level page**
(e.g. an external link you tap) is handed off to the system browser via
`Linking.openURL`. Sub-resources and sub-frames from CDNs keep loading so the
SPA renders correctly.

## 💳 Payments (Razorpay) inside a WebView — what to expect

- **Cards / netbanking / wallets:** work through the WebView.
- **UPI:** the checkout popup opens in a secondary WebView
  (`onOpenWindow` → `PopupWebView`). UPI *intent* payments opening third-party
  apps from a WebView can be unreliable — a **native** payment fork using
  `@razorpay/react-native-razorpay` (same backend `create-order`/verify
  endpoints) is the recommended future upgrade if UPI usage is high.
- Order placement itself (including Cash on Delivery) is a plain `POST` to
  `/api/v1/Orders` and works fully inside the app.

## 🧯 Troubleshooting

| Symptom | Likely cause / fix |
|---|---|
| Blank white screen | `webAppUrl` still the placeholder — set it in `app.json`, restart `expo start` with `-c`. |
| API calls failing | Backend CORS doesn't include the deployed origin (check `FRONTEND_URL_*`) or `VITE_PRODUCTION_URL` isn't set in the deployed frontend build. |
| Menu shows "Menu unavailable" / products empty | The live backend returns HTTP 500 `"Failed to fetch products"` — a pre-existing backend/DB config issue on the deployment (check `MONGO_URI` / env on Render). The website has the same behavior. |
| Image load errors | The image CDN host isn't in the allow-list — add it to `ALLOWED_HOSTS`. |
| "Can't reach the restaurant site" | No network or the web app host is down — check `webAppUrl` and try **Retry**. |
| **"Project is incompatible with this version of Expo Go"** | The project uses **Expo SDK 57**, but the Play Store's Expo Go build is older (Play releases lag behind). Two fixes below. ⬇️ |
| Expo Go can't connect | Both devices on the same Wi-Fi; try `npx expo start --tunnel`. |
| Expo Go can't connect | Both devices on the same Wi-Fi; try `npx expo start --tunnel`. |
### ℹ️ "This project requires a newer version of Expo Go" (SDK 57)

The Play Store version of Expo Go is **older than SDK 57** and can't run this project yet. Pick one:

**Option A — quick test (sideload the matching Expo Go client):**
Download and install the SDK-57-compatible Expo Go APK directly from Expo's official releases (it can sit alongside the Play Store version or replace it):
`https://github.com/expo/expo-go-releases/releases/download/Expo-Go-57.0.9/Expo-Go-57.0.9.apk`
Then re-scan the QR from `npx expo start`.

**Option B — recommended (skip Expo Go, use a development/preview build):**
This app is just a WebView wrapper, so it doesn't need Expo Go at all. `expo-dev-client` is already installed:
- Local (needs Android Studio): `npx expo run:android`
- Cloud (free Expo account): `npx eas-cli build -p android --profile development`
- **Store-ready APK (no dev server needed — loads the live site):** `npx eas-cli build -p android --profile preview`


| Payments don't open | Older Android WebView — update Android System WebView on the device. |
